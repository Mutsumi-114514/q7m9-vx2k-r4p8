# 单店损益数据合同 V0.1

> 定位：单店损益 A 阶段分析的稳定输入合同。  
> 目标：把口径、符号、原始记录处理、原子存在性与关键恒等式从项目状态文档中独立出来，作为后续 Data Gate、计算内核和 Skill 的共同 Source of Truth。

---

## 1. 当前支持的输入形态

内部表格整体规范，当前只要求识别两种形态：

### Wide Table（宽表）

```text
月份 | 门店 | 渠道 | 常规GMV | 仅双记GMV | 综合毛利 | ...
```

### Long / Unpivot Table（长表 / 逆透视表）

```text
月份 | 门店 | 渠道 | 科目属性 | 金额
```

输入适配只做：

```text
识别宽 / 长表
↓
字段词典匹配
↓
发现词典外字段时询问用户确认
↓
转为 Canonical Input
```

不设计万能脏表推断器，不对未知字段静默猜测。

---

## 2. 原始记录处理硬规则

当前事实表不要求：

```text
月份 × 门店 × 渠道 × 属性
```

唯一。

同一组合下可能存在多条合法记录。

因此：

1. 保留全部原始行；
2. 按目标分析粒度对金额执行 `SUM`；
3. 禁止未经业务确认使用 `drop_duplicates` 或类似自动去重；
4. 已关店、非门店、占位符不构成删除历史记录的理由；
5. 只有取得业务确认的原始唯一流水号，并能证明技术重复时，才允许提出去重方案。

> **分析汇总粒度不是原始物理主键。**

---

## 3. 基础格式、Null 与符号

```text
期间格式：YYYYMM
金额单位：万元
金额聚合：完整原始记录 SUM
0 值：合法值，不等于缺失
Null / Missing：未知或不存在，不得在状态分类前静默填 0
负值：合法业务记录，不自动取绝对值或按中文名称翻转
```

所有科目按源数据实际存储符号参与恒等式。

> **业务语义上“应扣减”不代表代码需要再次乘以 -1。**

尤其在 Base / Current Full Outer Join 后，必须先保留原子是否真实出现过的存在性信息，再决定是否对金额空值做计算层补 0。

至少保存：

```text
base_key_present
current_key_present
```

> **Absent（原子不存在）与 Zero（原子存在但净额为 0）不是同一状态。**

## 4. GMV 口径

```text
不含仅双记 GMV
= 常规 GMV - 仅双记 GMV
```

当前 A 阶段毛利率默认使用：

```text
不含仅双记 GMV
```

作为分母。

---

## 5. 毛利口径

若用户未额外限定：

> **“毛利 / 毛利率”默认指综合毛利 / 综合毛利率。**

定义：

```text
综合毛利率
= 综合毛利 / 不含仅双记 GMV
```

用户明确指定商品毛利、前台毛利或后台毛利时，切换到对应口径，不得静默混用。

### 商品毛利率

```text
商品毛利率
= 商品毛利 / 不含仅双记 GMV
```

### 前台毛利率

```text
前台毛利率
= 商品前台毛利 / 不含仅双记 GMV
```

### 后台毛利率

```text
后台毛利率
= 商品后台毛利 / 不含仅双记 GMV
```

当分母为 0 时：

> 毛利率为 N/A / 不适用，不得填 `0%` 冒充正常率。

## 6. 核心恒等式

所有字段按源数据符号参与计算。

```text
不含仅双记 GMV
= 常规 GMV - 仅双记 GMV

商品毛利
= 商品收入 - 商品成本 - 供应商支持

商品毛利
= 地采商品毛利 + 集采商品毛利 + 万家商品毛利 + 星选商品毛利

商品毛利
= 商品前台毛利 + 商品后台毛利

商品毛利率
= 前台毛利率 + 后台毛利率

综合毛利
= 商品毛利 + 其他毛利 + 主营业务税金及附加毛利

贡献利润
= 综合毛利 - 销售管理费用 + 补贴收入 + 营业外收入 - 营业外支出
```

已确认符号纪律：

- 供应商支持按源数据实际符号参与公式；
- 主营业务税金及附加毛利按源数据实际负值直接相加，不二次取反；
- 销售管理费用按源数据原值在贡献利润中扣减。

---

## 7. 商品毛利的三条平行观察路径

以下三条路径可以分别验证同一个商品毛利：

1. 商品收入－商品成本－供应商支持；
2. 地采＋集采＋万家＋星选；
3. 商品前台毛利＋商品后台毛利。

三条路径可以各自闭合，但不能把路径中的字段混合相加，否则会重复计算同一商品毛利。

---

## 8. Rate Never Rolls Up

累计率、父级率不得平均子级率。

```text
累计毛利率 = Σ毛利额 / ΣGMV
```

禁止：

- 平均月份毛利率；
- 平均门店毛利率；
- 平均渠道毛利率；
- 平均底层行毛利率。

同理，父级 GMV 同比应基于聚合后的本期 / 基期金额重新计算。

---

## 9. 校验层级与残差

核心恒等式至少应在以下层级验证：

1. 校验期间合计；
2. 月份；
3. 月份 × 门店；
4. 月份 × 门店 × 渠道。

残差统一定义：

```text
残差 = 公式左侧原值 - 公式右侧计算值
```

当前建议数值容差：

```text
max(0.0001 万元, 左右两侧绝对值较大者 × 10^-8)
```

正式实现至少输出：

- 净残差；
- 残差绝对值之和；
- 最大单行残差；
- 异常行数。

Closure Check 使用未舍入原值。

## 10. 官方控制数优先

工作流程：

```text
人工先核对官方报表关键合计
↓
确定性脚本汇总完整底层
↓
与人工确认控制数勾稽
↓
一致后才进入 WHERE / Mathematical WHY
```

关键控制数通常包括：

- 不含仅双记 GMV；
- 商品前台毛利；
- 商品后台毛利；
- 商品毛利；
- 综合毛利；
- 必要时贡献利润。

若脚本结果与已确认官方控制数不一致：

> 优先检查数据读取、聚合、符号和范围，不得通过删行、去重或改符号强行闭合。

## 11. 已确认的两个典型失败模式

### 11.1 税金负值二次取反

错误做法：

```text
综合毛利
= 商品毛利 + 其他毛利 - 主营业务税金及附加毛利
```

若税金字段本身已经为负，就发生二次取反。

正确：

```text
综合毛利
= 商品毛利 + 其他毛利 + 主营业务税金及附加毛利
```

### 11.2 自动去重删除合法记录

错误做法：

```text
drop_duplicates(月份, 门店, 渠道, 属性)
```

会把合法多条记录误删。

正式规则：

> 未取得业务确认的原始唯一流水号前，不允许自动去重。

## 12. Period State：机器码 / 中文标准术语 / 可执行定义

状态必须首先由确定性字段和原子存在性定义，不使用现实因果名称作为底层 Machine Code。

### 12.1 Period State 对照表

| Machine Code | 中文标准名 | 可执行定义 | 业务展示语言 |
|---|---|---|---|
| `ABSENT` | 无原子记录 | 当前期间该原子 Key 不存在，`key_present = false` | 当前期间没有该业务原子记录 |
| `STANDARD` | 标准业务状态 | `key_present = true`，必要字段有效，`GMV > 0`，毛利率可定义 | 可进入普通 Bennett / Mix-Rate 的正常状态 |
| `NET_ZERO_PRESENT` | 有记录但净额归零 | `key_present = true`，聚合后 `GMV = 0` 且 `毛利 = 0` | 存在记录但净金额归零，不等于没有业务 |
| `ZERO_GMV_NONZERO_GP` | 零GMV非零毛利 | `key_present = true`，`GMV = 0` 且 `毛利 ≠ 0` | 存在无法计算正常毛利率的非标准毛利金额 |
| `NEGATIVE_GMV` | 负GMV状态 | `key_present = true`，`GMV < 0` | 不进入普通权重 / Mix-Rate，走非标准路径 |
| `INVALID_OR_MISSING` | 数据缺失或无效 | Key 存在但必要字段缺失、类型错误或无法满足指标合同 | 当前数据不足以进入正常计算 |
| `OTHER_NONSTANDARD` | 其他非标准状态 | 已有明确机械判定规则、但不属于以上状态 | 需携带具体 boundary reason，不得作为无解释兜底桶 |

`OTHER_NONSTANDARD` 只有在已经存在额外可执行判定规则时才能使用；不能把“AI 觉得不正常”直接写入该状态。

### 12.2 为什么不再用 `ADJUSTMENT` 作为底层状态名

```text
GMV = 0
毛利 ≠ 0
```

只能证明数值状态，不能证明现实原因就是“调整 / 返利 / 冲销”。

因此底层 Machine Code 使用：

```text
ZERO_GMV_NONZERO_GP
```

“调整项”等业务名称只能在额外 Evidence 或业务字段明确支持后作为更高层标签。

### 12.3 `NET_ZERO_PRESENT` 不等于 `ABSENT`

例如同一原子存在两条合法记录：

```text
记录1：GMV +100，毛利 +20
记录2：GMV -100，毛利 -20
```

聚合后：

```text
GMV = 0
毛利 = 0
```

该原子属于：

```text
NET_ZERO_PRESENT
```

而不是 `ABSENT`。

因此禁止在 Full Outer Join 后先把缺失 Key 与真实净零状态一起填成 0，再分类 Period State。

## 13. Transition Type 对照表

跨期状态由：

```text
base_state + current_state
```

确定。

| Machine Code | 中文标准名 | 条件 | 允许的基础解释 |
|---|---|---|---|
| `CONTINUING_STANDARD` | 标准存量业务 | `STANDARD → STANDARD` | 两期均为标准业务 |
| `PURE_ENTRY` | 纯新增业务 | `ABSENT → STANDARD` | 基期无该原子记录，本期进入标准业务 |
| `PURE_EXIT` | 纯退出业务 | `STANDARD → ABSENT` | 基期为标准业务，本期无该原子记录 |
| `NONSTANDARD_TRANSITION` | 非标准状态迁移 | 任一期为非标准 / 无效率状态，且不满足其他明确类型 | 保留真实金额与状态，不强行拆普通因素 |
| `FULL_MEMBERSHIP_REPLACEMENT` | 标准业务集合完全替换 | Parent 两期均有标准业务，但 Continuing Standard Set 为空 | 无共同存量，普通 Mix / Rate 不适用 |
| `BOUNDARY_STOP` | 边界终止 | Parent 或原子必要分母 / 数据合同不满足 | 当前路径停止，不输出假分解 |

注意：

```text
NET_ZERO_PRESENT → STANDARD
```

**不自动等于 `PURE_ENTRY`**；

```text
STANDARD → NET_ZERO_PRESENT
```

**不自动等于 `PURE_EXIT`**。

这类状态默认进入 `NONSTANDARD_TRANSITION`，除非后续有独立业务规则证明应按 Entry / Exit 解释。

## 14. Machine Code 与中文显示的统一纪律

所有重要枚举应至少维护：

```text
machine_code
zh_cn_label
executable_definition
display_guidance
```

原则：

1. Machine Code 用于程序和测试；
2. 中文标准名用于业务阅读与文档；
3. AI 不得自行给 Machine Code 发明新的中文译名；
4. 中文标准名同样不能越权加入现实因果；
5. 自然语言解释必须建立在 Machine Code + 中文标准名之上，而不是替代结构化状态。

未来 View Type、Boundary、Unit、Decomposition Type 等枚举也遵循同一规则。

## 16. 当前合同边界

本数据合同只负责：

> **数据是什么、怎样安全读取、怎样验证口径、怎样机械识别 Period State。**

- Attention 阈值；

- 现实经营原因；
- 行动建议。
