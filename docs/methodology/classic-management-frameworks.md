# 经典管理方法在经营分析体系中的适配

> 文档定位：方法论适配层  
> 适用范围：经营分析、财务 BP、AI Skill / Workflow、数据与文件治理  
> 原则：不为引用管理学名词而引用，只吸收能稳定改善分析与执行质量的部分。

---

## 1. 总体判断

经典管理工具并非都需要完整移植到经营分析体系。更合适的做法是把它们映射到已经存在的分析流程：

```text
Data → What → Where → Why → Evidence → Action → Feedback
```

当前建议：

| 方法 | 适配度 | 在本体系中的主要位置 | 采用方式 |
|---|---:|---|---|
| 二八原理 / Pareto | 高 | WHERE、重大性、注意力管理 | 核心吸收 |
| 5W2H | 高 | Evidence、业务访谈、Action | 核心吸收 |
| PDCA | 高 | Shadow Test、规则迭代、持续校准 | 作为治理原则 |
| SMART | 较高 | Action 定义与验收 | 有条件采用 |
| 时间管理四象限 | 中 | 问题池优先级 | 辅助使用 |
| 6S 现场管理 | 低（原义）/高（赛博化） | 数据、文件、工具、AI 上下文治理 | 转化为“赛博6S管理” |

原则上，不把经典工具平铺成新的分析框架，而是让它们成为现有经营分析流程中的局部增强件。

---

## 2. 二八原理：关键少数优先

二八原理在本体系中不应机械理解为“永远 80% 的结果来自 20% 的对象”。真正需要吸收的是：

> **优先寻找能够解释大部分结果变化的关键少数。**

典型应用：

- 哪些门店解释了主要 GMV 或利润变化；
- 哪些渠道、品类、品牌承载主要差异；
- 哪些问题值得进入深度 WHY；
- 哪些异常只应进入观察池。

因此，Pareto 的核心位置是：

```text
WHERE + Materiality + Attention Management
```

经营分析首先是注意力管理，而不是数据考古。

---

## 3. 5W2H：连接 Evidence 与 Action

5W2H 不负责数学归因，主要用于把已经定位的问题转化为可验证、可执行的现实问题。

| 要素 | 在经营分析中的解释 |
|---|---|
| What | 具体发生了什么 |
| Where | 发生在哪个门店、渠道、品类、品牌或业务环节 |
| When | 从什么时候开始，是否持续 |
| Why | 当前有哪些待验证原因 |
| Who | 谁能提供证据、谁负责处理 |
| How | 如何验证、如何改善 |
| How much | 影响金额、规模、改善空间有多大 |

建议主要用于：

- 业务访谈问题设计；
- Evidence 清单；
- Action 方案；
- 跨部门沟通。

核心原则：

> 前半程尽量用数据缩小问题空间，后半程再用 5W2H 把问题带入现实世界。

---

## 4. PDCA：方法论本身也要被验证

PDCA 最适合用来治理分析方法，而不是在每份报告中机械展示四个步骤。

### Plan

提出新的分析规则、阈值、下钻路径或算法。

### Do

在真实工作中执行，必要时先通过 Shadow Test 后台并行。

### Check

检查：

- 是否发现旧方法漏掉的重要问题；
- 新发现是否被 Evidence 证实；
- 是否真正改变判断或行动；
- 是否增加误报、解释成本和维护成本。

### Act

决定：

- 正式上线；
- 调整规则；
- 限定使用场景；
- 或删除复杂度。

因此：

> **Shadow Test 是 PDCA 在分析算法与规则治理中的一种具体实现。**

---

## 5. SMART：约束 Action，而不是强迫所有分析都有行动

SMART 适合用于已经明确需要改善的行动项：

- Specific：具体；
- Measurable：可衡量；
- Attainable：可达成；
- Relevant：与问题相关；
- Time-bound：有明确时间边界。

例如，不建议输出：

> 加强空调销售。

更好的 Action 应明确：

- 谁负责；
- 什么时间前完成；
- 检查哪些对象；
- 目标是什么；
- 如何验收。

但必须保留克制原则：

> **不是所有经营分析都必须形成 SMART Action。**

当证据不足时，正确动作可能只是继续观察或补充 Evidence，不能为了“闭环”强行制造行动项。

---

## 6. 时间管理四象限：作为问题池优先级辅助

时间管理四象限的“重要 / 紧急”可以辅助分析问题池排序：

| | 紧急 | 不紧急 |
|---|---|---|
| 重要 | 立即处理 | 纳入专项、持续推进 |
| 不重要 | 快速处理或委派 | 不处理或低优先级观察 |

在经营分析中，“重要”更接近重大性和决策影响，“紧急”更接近可干预窗口和时间敏感性。

例如：

- 关账前发现大额返利遗漏：重要且紧急；
- 某店型连续半年效率下降：重要但不紧急，应形成专项；
- 小金额数据异常：可能紧急，但主要属于数据修复；
- 小金额且不影响决策的波动：通常无需投入分析资源。

该框架只辅助排优先级，不替代重大性、异常性、持续性等经营判断。

## 7. 赛博6S管理

传统 6S 来自现场管理：整理、整顿、清扫、清洁、素养、安全。原义不必直接移植，但它非常适合作为数字工作环境的治理隐喻。

本项目将其转化为：

> **赛博6S管理（Cyber 6S）——对数据、文件、代码、Skill、AI 上下文和工作流进行持续的数字现场治理。**

### 7.1 整理 Sort

区分“需要”和“不需要”，减少数字垃圾与认知负担。

典型动作：

- 删除或归档废弃临时文件；
- 标记过期规则、旧版本模板和已废弃 Skill；
- 不把重复说明长期散落在多个文档；
- 控制 AI 上下文，只加载当前任务真正需要的知识。

目标：

> 减少噪声、重复知识和上下文污染。

### 7.2 整顿 Set in Order

让需要的东西有稳定位置、名称和调用方式。

典型动作：

- 统一目录与命名规则；
- 明确 Source of Truth；
- 方法论、数据合同、状态文档、Skill 实现分层保存；
- 对文件、数据版本、校验凭证建立可追踪关系。

目标：

> 让人和 AI 都能快速找到正确版本，而不是“记得好像在哪”。

### 7.3 清扫 Shine

持续发现并清理数字现场中的故障与脏点。

典型动作：

- 修复失效链接、错误引用、过期路径；
- 清理无效缓存、中间产物和测试残留；
- 发现并记录数据异常、脚本错误和错误口径；
- 定期检查 Skill 是否仍能在当前环境运行。

目标：

> 问题不只修一次，还要留下可追踪的修复痕迹。

### 7.4 清洁 Standardize

把已经验证有效的整理、整顿、清扫动作标准化。

典型动作：

- Data Contract；
- Data Gate；
- 文件命名和目录规范；
- 版本绑定；
- Known Failure Modes；
- 固定测试与校验清单；
- 稳定的 README / Handoff 导航。

目标：

> 从“这次处理好了”升级为“以后不容易再次出错”。

### 7.5 素养 Sustain / Discipline

让规则成为默认习惯，而不是一次性的整理活动。

典型动作：

- 新方法先验证再上线；
- 修改数据合同必须留下依据；
- 已关闭问题没有新证据不随意重开；
- 每完成一个阶段更新状态与文档；
- AI 和人工都遵守同一套数据与分析纪律。

目标：

> 让治理成本逐渐下降，而不是靠某个人持续救火。

### 7.6 安全 Safety

安全在数字工作环境中不仅是信息安全，也包括源数据安全和分析安全。

典型动作：

- GitHub 不保存真实经营数据、账号、Token 和敏感地址；
- 原始文件默认只读；
- 自动化不擅自删除、覆盖、去重或修改源数据；
- 权限最小化；
- 关键修改保留版本和回滚路径；
- AI 不能把未知、推断和事实混为一谈。

目标：

> 防止数据泄露、源数据破坏、不可逆修改和错误结论扩散。

## 8. 赛博6S与当前仓库治理的对应关系

当前项目已经存在一些赛博6S实践：

| 当前实践 | 主要对应 |
|---|---|
| 稳定方法论与项目状态分离 | 整理 / 整顿 |
| README 作为入口导航 | 整顿 |
| Data Contract | 清洁 |
| Data Gate | 清洁 / 安全 |
| 禁止未经确认的去重和符号修改 | 安全 / 素养 |
| Known Failure Modes 思路 | 清扫 / 清洁 |
| Shadow Test | 素养 / PDCA |
| GitHub 不保存真实经营数据与凭证 | 安全 |

因此“赛博6S”不是额外制造一套繁重流程，而是给已经在发生的数字治理动作一个统一视角。

---

## 9. 最终整合

这些经典方法在本体系中的位置可以压缩为：

```text
数据与环境治理：赛博6S
        ↓
发现关键少数：Pareto
        ↓
WHAT → WHERE → WHY
        ↓
现实验证：5W2H
        ↓
行动设计：SMART
        ↓
问题池优先级：重要 / 紧急
        ↓
方法与规则自我校准：PDCA + Shadow Test
```

核心原则仍然不变：

> **经典方法只有在能够降低认知成本、提升决策质量或增强执行闭环时才值得保留；不为了管理学形式完整而增加流程。**
