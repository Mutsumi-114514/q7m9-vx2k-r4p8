# 单店损益数据合同 V0.1

> **Bundled Runtime Snapshot**：本文件是可安装 Skill 内置的数据合同快照，来源于 `docs/data-contracts/store-pnl-data-contract.md`。  
> 定位：单店损益 A 阶段稳定输入合同。

---

## 1. 当前支持的输入形态

### Wide Table（宽表）

```text
月份 | 门店 | 渠道 | 常规GMV | 仅双记GMV | 综合毛利 | ...
```

### Long / Unpivot Table（长表 / 逆透视表）

```text
月份 | 门店 | 渠道 | 科目属性 | 金额
```

输入适配只做：

```text
识别宽 / 长表
→ 字段词典匹配
→ 词典外字段询问用户确认
→ 转为 Canonical Input
```

不设计万能脏表推断器，不对未知字段静默猜测。

---

## 2. 原始记录处理硬规则

当前事实表不要求 `月份 × 门店 × 渠道 × 属性` 唯一。

同一组合下可能存在多条合法记录，因此：

1. 保留全部原始行；
2. 按目标分析粒度对金额执行 `SUM`；
3. 禁止未经业务确认使用自动去重；
4. 已关店、非门店、占位符不构成删除历史记录的理由；
5. 只有取得业务确认的原始唯一流水号，并能证明技术重复时，才允许提出去重方案。

> **分析汇总粒度不是原始物理主键。**

---

## 3. 基础格式、Null 与符号

```text
期间格式：YYYYMM
金额单位：万元
金额聚合：完整原始记录 SUM
0 值：合法值，不等于缺失
Null / Missing：未知或不存在，不得在状态分类前静默填 0
负值：合法业务记录，不自动取绝对值或按中文名称翻转
```

所有科目按源数据实际存储符号参与恒等式。

尤其在 Base / Current Full Outer Join 后，必须先保留：

```text
base_key_present
current_key_present
```

> **Absent 与 Zero 不是同一状态。**

---

## 4. GMV 口径

```text
不含仅双记 GMV
= 常规 GMV - 仅双记 GMV
```

当前 A 阶段毛利率默认使用不含仅双记 GMV 作为分母。

---

## 5. 毛利口径

若用户未额外限定：

> **“毛利 / 毛利率”默认指综合毛利 / 综合毛利率。**

```text
综合毛利率 = 综合毛利 / 不含仅双记 GMV
商品毛利率 = 商品毛利 / 不含仅双记 GMV
前台毛利率 = 商品前台毛利 / 不含仅双记 GMV
后台毛利率 = 商品后台毛利 / 不含仅双记 GMV
```

分母为 0 时，毛利率为 N/A，不得填 `0%` 冒充正常率。

---

## 6. 核心恒等式

所有字段按源数据符号参与计算：

```text
不含仅双记 GMV
= 常规 GMV - 仅双记 GMV

商品毛利
= 商品收入 - 商品成本 - 供应商支持

商品毛利
= 地采商品毛利 + 集采商品毛利 + 万家商品毛利 + 星选商品毛利

商品毛利
= 商品前台毛利 + 商品后台毛利

商品毛利率
= 前台毛利率 + 后台毛利率

综合毛利
= 商品毛利 + 其他毛利 + 主营业务税金及附加毛利

贡献利润
= 综合毛利 - 销售管理费用 + 补贴收入 + 营业外收入 - 营业外支出
```

已确认符号纪律：

- 供应商支持按源数据实际符号参与公式；
- 主营业务税金及附加毛利按源数据实际负值直接相加，不二次取反；
- 销售管理费用按源数据原值在贡献利润中扣减。

---

## 7. 商品毛利三条平行观察路径

以下三条路径分别验证同一个商品毛利：

1. 商品收入－商品成本－供应商支持；
2. 地采＋集采＋万家＋星选；
3. 商品前台毛利＋商品后台毛利。

三条路径可以各自闭合，但不能把路径中的字段混合相加，否则会重复计算。

---

## 8. Rate Never Rolls Up

累计率、父级率不得平均子级率。

```text
累计毛利率 = Σ毛利额 / ΣGMV
```

禁止平均月份、门店、渠道或底层行毛利率。

父级 GMV 同比同样基于聚合后的本期 / 基期金额重算。

---

## 9. 校验层级与残差

核心恒等式至少在以下层级验证：

1. 校验期间合计；
2. 月份；
3. 月份 × 门店；
4. 月份 × 门店 × 渠道。

```text
残差 = 公式左侧原值 - 公式右侧计算值
```

当前建议容差：

```text
max(0.0001 万元, 左右两侧绝对值较大者 × 10^-8)
```

至少输出：净残差、残差绝对值之和、最大单行残差、异常行数。

Closure 使用未舍入原值。

---

## 10. 官方控制数优先

流程：

```text
人工先核对官方报表关键合计
→ 确定性汇总完整底层
→ 与控制数勾稽
→ 一致后才进入 WHERE / Mathematical WHY
```

关键控制数通常包括：不含仅双记 GMV、商品前台毛利、商品后台毛利、商品毛利、综合毛利，必要时贡献利润。

若脚本结果与已确认官方控制数不一致，优先检查数据读取、聚合、符号和范围，不得通过删行、去重或改符号强行闭合。

## 11. 典型失败模式

### 税金负值二次取反

若税金字段本身已经为负，禁止再次减去该字段。

正确：

```text
综合毛利
= 商品毛利 + 其他毛利 + 主营业务税金及附加毛利
```

### 自动去重删除合法记录

未取得业务确认的原始唯一流水号前，不允许自动去重。

## 12. Period State

| Machine Code | 中文标准名 | 可执行定义 |
|---|---|---|
| `ABSENT` | 无原子记录 | 当前期间该原子 Key 不存在，`key_present=false` |
| `STANDARD` | 标准业务状态 | Key 存在、必要字段有效、`GMV>0`、毛利率可定义 |
| `NET_ZERO_PRESENT` | 有记录但净额归零 | Key 存在，聚合后 `GMV=0` 且 `毛利=0` |
| `ZERO_GMV_NONZERO_GP` | 零GMV非零毛利 | Key 存在，`GMV=0` 且 `毛利≠0` |
| `NEGATIVE_GMV` | 负GMV状态 | Key 存在，`GMV<0` |
| `INVALID_OR_MISSING` | 数据缺失或无效 | Key 存在但必要字段缺失 / 类型错误 / 不满足指标合同 |
| `OTHER_NONSTANDARD` | 其他非标准状态 | 已有明确机械判定规则且不属于以上状态 |

`OTHER_NONSTANDARD` 不能作为“AI 觉得不正常”的兜底桶。

`GMV=0, 毛利≠0` 只能证明数值状态，不能自动证明现实原因是“调整 / 返利 / 冲销”。

`NET_ZERO_PRESENT` 不等于 `ABSENT`。

---

## 13. Transition Type

| Machine Code | 中文标准名 | 条件 |
|---|---|---|
| `CONTINUING_STANDARD` | 标准存量业务 | `STANDARD → STANDARD` |
| `PURE_ENTRY` | 纯新增业务 | `ABSENT → STANDARD` |
| `PURE_EXIT` | 纯退出业务 | `STANDARD → ABSENT` |
| `NONSTANDARD_TRANSITION` | 非标准状态迁移 | 任一期为非标准 / 无效率状态，且不满足其他明确类型 |
| `FULL_MEMBERSHIP_REPLACEMENT` | 标准业务集合完全替换 | Parent 两期均有 Standard，但 Continuing Set 为空 |
| `BOUNDARY_STOP` | 边界终止 | Parent 或原子必要分母 / 数据合同不满足 |

`NET_ZERO_PRESENT → STANDARD` 不自动等于 PURE_ENTRY；`STANDARD → NET_ZERO_PRESENT` 不自动等于 PURE_EXIT。
